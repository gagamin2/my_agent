文件主要作用说明
================

一、src/index.ts 的主要作用
--------------------------------

src/index.ts 是整个应用程序的入口文件（Entry Point），负责启动和串联整个 Agent 流程。它的核心职责如下：

1. 加载环境变量
   - 文件开头通过 `import "dotenv/config"` 引入 dotenv 库，自动读取项目根目录下的 `.env` 文件，并把其中的配置（例如 DEEPSEEK_API_KEY 等 API 密钥）加载到 `process.env` 中，为后续创建 OpenAI 客户端、调用 DeepSeek 模型提供必要的鉴权信息。

2. 引入核心模块
   - 从 `./agent/agent.js` 中引入 `runAgent` 函数。`runAgent` 是 Agent 的主执行入口，负责与模型进行多轮对话、调用工具并返回最终结果。
   - 从 `./tools/readFile.js` 中引入 `readFile` 工具函数，说明该入口文件也有直接使用文件读取工具的能力（当前代码中该调用被注释掉，作为备用示例保留）。

3. 定义并执行 main 异步函数
   - `main()` 是程序的启动函数，使用 `async` 声明，以支持 `await` 异步调用。
   - 在 `main()` 中，当前实际执行的是：
     `const result = await runAgent("请读取 src/index.ts 和 src/agent/agent.ts，然后分别告诉我这两个文件的主要作用，然后把你对它们主要作用的说明写入src/text.txt,要详细一点，并覆盖之前的版本。")`
     也就是说，入口文件会调用 `runAgent`，把一段中文用户指令作为输入传给 Agent，让 Agent 自动完成“读取两个源码文件 → 分析各自作用 → 写入 src/text.txt 并覆盖旧版本”的完整任务。
   - 代码中还保留了两段被注释掉的示例调用：
     a) 让 Agent 做自我介绍的调用；
     b) 直接调用 `readFile("./src/index.ts")` 读取文件的调用。
     这些注释说明了该入口文件也常用于调试或验证单个工具函数。

4. 输出最终结果
   - `main()` 的最后使用 `console.log(result)` 把 `runAgent` 返回的最终结果打印到控制台，方便开发者查看 Agent 的执行结论。

5. 启动程序
   - 文件末尾直接调用 `main()`，当运行 `src/index.ts` 时，Node.js 会立即执行 `main()`，从而启动整个 Agent 流程。

总结：src/index.ts 是程序的“发令枪”和“装配线”，负责加载配置、引入 Agent 与工具、定义启动任务、执行任务并输出结果。它本身不实现复杂的 Agent 逻辑，而是把具体工作委托给 `runAgent` 完成。

二、src/agent/agent.ts 的主要作用
--------------------------------

src/agent/agent.ts 是整个项目的核心文件，它实现了一个可以调用工具的 AI Agent（智能体）主循环。其核心职责如下：

1. 引入依赖与工具
   - 引入 OpenAI 官方 SDK：`import OpenAI from "openai"`，用于调用兼容 OpenAI 接口的模型服务。
   - 引入类型 `ChatCompletionMessageParam`，用于约束对话消息的数据结构，保证类型安全。
   - 引入本地工具函数 `readFile`（读取文件）和 `writeFileTool`（写入文件），供 Agent 在运行时实际调用。

2. 设置保险丝（最大执行轮数）
   - 定义常量 `MAX_TURNS = 10`，作为 Agent 的最大执行轮数限制，防止模型陷入无限循环或产生过多工具调用，保证程序最终一定能终止。
   - 当循环达到该上限时，`runAgent` 会返回“Agent 达到最大执行轮数，已停止。”作为兜底结果。

3. 创建模型客户端
   - 使用 `new OpenAI({...})` 创建客户端实例。
   - `baseURL` 设置为 `"https://api.deepseek.com"`，说明实际调用的是 DeepSeek 提供的模型接口。
   - `apiKey` 从环境变量 `process.env.DEEPSEEK_API_KEY` 中读取，保证密钥不硬编码在源码中。

4. 定义工具列表（tools）
   - `tools` 数组中声明了两个可供模型调用的函数工具：
     a) `read_file`：读取指定文件的内容，参数为 `filePath`（必填）。
     b) `write_file`：向指定文件写入内容，参数为 `filePath` 和 `content`（均为必填）。
   - 每个工具都按照 OpenAI Function Calling 的 JSON Schema 格式编写，包含 `type: "function"`、`name`、`description` 和 `parameters`，以便模型理解何时以及如何调用这些工具。

5. 实现工具执行器 executeTool
   - `executeTool(name, argumentsString)` 负责根据工具名称分派并执行具体工具。
   - 首先用 `JSON.parse(argumentsString)` 把模型传入的 JSON 字符串参数解析成对象。
   - 如果工具名是 `read_file`，则调用 `readFile(args.filePath)` 读取文件。
   - 如果工具名是 `write_file`，则调用 `writeFileTool(args.filePath, args.content)` 写入文件。
   - 如果遇到未知工具名，则抛出错误 `Unknown tool: xxx`，避免执行非法操作。

6. 实现 Agent 主循环 runAgent
   - `runAgent(userInput)` 是 Agent 的对外入口，接收用户的自然语言指令。
   - 初始化 `messages` 对话记录数组，首先放入一条 `role: "user"` 的消息，内容就是用户输入。
   - 使用 `while(i < MAX_TURNS)` 循环，最多执行 10 轮：
     a) 每轮开始时打印当前轮数，便于调试观察。
     b) 调用 `client.chat.completions.create({ model: "deepseek-v4-pro", messages, tools })`，把对话历史和工具定义一起发给模型。模型会返回文本回复或工具调用请求。
     c) 把模型返回的 `message` 追加到 `messages` 中，并用 `console.dir` 打印完整消息。
     d) 如果模型没有返回 `tool_calls`，说明模型已经给出最终答案，直接返回 `message.content`，循环结束。
     e) 如果模型返回了 `tool_calls`，则遍历所有工具调用：
        - 跳过类型不是 `function` 的调用；
        - 对每个函数工具调用，取出工具名和参数，交给 `executeTool` 执行；
        - 打印工具执行结果；
        - 把工具结果以 `role: "tool"`、`tool_call_id` 和字符串化的结果内容追加回 `messages`，让模型在下一轮可以看到工具返回的信息。
     f) 每轮结束时打印“Agent 第 i 轮已结束”。
     g) 如果循环次数达到 `MAX_TURNS`，返回达到最大轮数的提示信息。
   - 代码中被注释掉的部分显示了一个简化版的“第二次调用模型”思路：即执行完工具后立即再次请求模型并返回结果。当前实现则采用了更通用的 `while` 循环方式，可以支持连续多轮工具调用，直到模型给出最终答案或达到轮数上限。

总结：src/agent/agent.ts 实现了一个基于 OpenAI 兼容接口和 Function Calling 的 Agent 执行引擎。它把“用户指令 → 模型决策 → 调用工具 → 返回结果 → 再次决策”的循环封装在 `runAgent` 中，并通过 `read_file`、`write_file` 两个工具赋予 Agent 读取和写入文件的能力。该文件是让 Agent 能够自主完成“读取源码、分析作用、写入说明文件”等任务的关键核心。
