# Testing Skill

## 作用

用于帮助 Agent 对项目代码、功能和修改结果进行测试，
判断当前实现是否正常，并分析测试结果。

核心流程：

`理解测试目标 → 收集信息 → 确定测试方式 → 执行测试 → 分析结果 → 输出结论`

## 使用场景

当用户要求：

- 测试某个功能
- 运行测试
- 验证代码是否正常
- 验证 Bug 修复
- 检查功能是否通过
- 检查构建是否成功
- 检查 TypeScript 是否存在错误
- 分析测试失败原因

时使用此 Skill。

如果用户要求修改代码并解决测试失败，
可以在 Testing 完成问题定位后进入 Debugging 流程。

## 核心原则

1. 测试必须基于实际代码和实际执行结果。
2. 不要在没有明确测试目标的情况下随意执行大量测试。
3. 优先使用项目已有的测试配置和测试命令。
4. 不要为了让测试通过而修改测试代码。
5. 不要为了让测试通过而修改无关配置。
6. 不要把推测结果当成实际测试结果。
7. 测试完成后必须根据实际执行结果给出结论。
8. 如果测试失败，应明确说明失败原因或当前无法确定的部分。
9. 如果无法执行测试，应明确告诉用户原因。

## 执行流程

### 1. 理解测试目标

首先明确：

- 用户要求测试什么
- 测试哪个文件、模块或功能
- 用户希望验证什么结果

如果用户指定了具体文件，
优先围绕指定文件进行测试。

### 2. 了解项目测试结构

如果不了解项目测试结构：

使用 `list_files` 查看相关目录。

重点寻找：

- `tests`
- `test`
- `__tests__`
- 测试配置文件
- `package.json`

不要为了测试而读取整个项目。

### 3. 查找已有测试

如果项目已经存在测试：

优先使用已有测试。

可以使用：

- `search_files`
- `read_file`

寻找：

- 测试文件
- 测试命令
- 测试框架
- 与目标代码相关的测试

不要重复创建已有测试。

### 4. 确定测试方式

根据项目实际情况选择测试方式。

例如：

- TypeScript 类型检查 → `npx tsc --noEmit`
- 项目构建 → `npm run build`
- 单元测试 → 使用项目已有测试命令
- 指定测试文件 → 使用项目支持的单文件测试方式

必须优先使用项目已经配置好的测试方式。

不要根据猜测执行不存在的命令。

### 5. 执行测试

使用 `run_command` 执行确定的测试命令。

测试命令应该与用户的测试目标直接相关。

不要重复执行完全相同的测试命令，
除非：

- 修改了代码
- 测试环境发生变化
- 需要确认之前的结果

### 6. 分析测试结果

根据实际命令输出判断：

- 是否执行成功
- 是否存在错误
- 错误发生在哪里
- 是否与当前测试目标相关

区分：

**事实：**

来自实际命令输出、测试结果和源码的信息。

**推测：**

目前无法完全确认的原因。

不要把推测当成测试结论。

### 7. 测试失败

如果测试失败：

- 不要直接修改代码
- 先分析错误信息
- 确定失败原因
- 如果需要修改代码，再进入 Debugging 流程

Testing Skill 本身主要负责：

`测试 → 发现问题 → 分析测试结果`

Debugging Skill 负责：

`定位问题 → 修改代码 → 再次验证`

### 8. 验证修改结果

如果测试失败后进入 Debugging：

修改完成后必须重新执行相关测试。

确认：

- 原测试是否通过
- 是否产生新的错误
- 是否影响其他功能

### 9. 测试完成

当已经获得足够的测试结果后：

- 停止继续调用工具
- 整理测试结果
- 明确告诉用户测试是否通过

不要为了“看得更全面”而无限执行测试。

## 修改范围

Testing Skill 默认不修改代码。

如果只是测试：

- 不修改源代码
- 不修改测试代码
- 不修改配置文件
- 不删除文件

如果测试失败并需要修复：

应交给 Debugging Skill 处理。

## 禁止事项

测试过程中：

- 不要修改 `tsconfig.json` 来隐藏 TypeScript 错误
- 不要修改 `package.json` 来绕过测试
- 不要关闭测试规则
- 不要跳过失败测试
- 不要修改测试代码制造通过结果
- 不要删除失败测试
- 不要通过降低检查标准制造“测试通过”

## 最终输出

测试完成后，应说明：

1. 测试对象
2. 使用的测试方式
3. 执行的命令
4. 测试结果
5. 如果失败，说明失败原因
6. 如果修复过，说明修复内容
7. 最终是否通过

例如：

测试对象：

`src/tools/readFile.ts`

测试命令：

`npm test`

结果：

测试通过。

或者：

测试命令：

`npx tsc --noEmit`

结果：

TypeScript 类型检查失败。

原因：

`xxx.ts` 中存在类型错误。

## 最终原则

**测试结论必须来自实际执行结果，而不是模型推测。**

测试失败时：

**先分析，再决定是否进入 Debugging。**

测试通过后：

**停止继续测试并输出结果。**
