# Community Skill Recommendation

当 Agent 获取到 SkillHub 社区的新 Skill 时，需要对这些 Skill 进行分析和推荐。

## 分析目标

不要简单复述 Skill 列表。

需要根据 Skill 的名称、描述、分类、标签以及社区数据，判断它是否值得用户关注。

## 分析维度

### 1. 实用性

判断 Skill 是否能够解决实际开发或 Agent 开发中的问题。

### 2. 通用性

判断 Skill 是否适用于多个项目，而不是只针对非常特殊的场景。

### 3. 社区热度

可以参考：

- downloads
- stars
- installs
- score

但不能仅根据这些数字决定推荐等级。

### 4. 新颖性

判断 Skill 是否提供了比较新的能力、工作流或解决方案。

### 5. 安全性

重点关注 Skill 是否涉及：

- 执行代码
- 执行 Shell 命令
- 文件系统访问
- 网络请求
- 安装依赖
- 修改系统
- 访问敏感数据

存在明显安全风险时，不应该给出强烈推荐。

## 推荐等级

使用以下三个等级：

### ⭐ 强烈推荐

满足以下条件中的多个：

- 实用性高
- 通用性较强
- 有明确的使用场景
- 有一定社区认可度
- 没有明显安全风险

### 🟡 可以关注

Skill 有一定价值，但存在以下情况之一：

- 使用场景比较有限
- 社区数据较少
- 功能比较普通
- 信息不足以判断

### ⚪ 暂不推荐

存在以下情况之一：

- 实际价值较低
- 使用场景非常有限
- 描述不清晰
- 功能与常见 Skill 高度重复
- 存在明显安全风险

## 输出要求

每个推荐的 Skill 都应该说明：

1. Skill 名称
2. 推荐等级
3. 推荐理由
4. 适合什么场景
5. 如果存在明显风险，需要说明风险

不要编造 Skill 描述中不存在的功能。

如果信息不足，明确说明“信息不足”，不要自行推测。

## 重要规则

本次推荐只能基于 `get_community_skills` 当前调用返回的 Skill。

如果工具返回空列表，表示当前没有发现新的 Skill。

此时不要重新推荐历史消息中的 Skill，也不要把以前见过的 Skill 当作新的 Skill。

## 数据来源规则

只能根据 `get_community_skills` 当前调用返回的数据进行分析。

不要补充工具结果中不存在的事实。

对于作者、认证状态、API Key、开源状态、功能、安全风险等信息，如果当前返回数据无法确认，应明确说明“信息不足”，不要自行推测。

不要声称结果是“最新”“最热门”或“最受欢迎”，除非当前工具返回的数据能够直接支持这一结论。

如果工具返回了分页信息，只能将其理解为当前分页结果。
