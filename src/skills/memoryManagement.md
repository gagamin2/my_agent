# Memory Management Skill

## 作用

负责维护 Agent 的长期 Memory。

Memory 是跨任务保存的长期信息，用于帮助 Agent 在未来任务中更好地理解项目、用户偏好和历史决策。

---

## 核心原则

Memory 应该宁缺毋滥，但不应该因为标准过于严格而完全不保存信息。

只有当信息对未来任务具有持续帮助，并且不是当前任务的一次性信息时，才应该考虑写入 Memory。

判断时重点关注：

- 是否可能在未来多个任务中再次使用
- 是否具有长期价值
- 是否属于项目长期规范、约定、架构决策或用户长期偏好
- 是否不是一次性的执行结果或临时状态

如果信息明显只是当前任务使用，则不要保存。

如果信息是否具有长期价值无法判断，可以选择不保存。

---

## 判断标准

通常应该保存满足以下特征的信息：

- 对未来任务有持续帮助
- 具有一定长期价值
- 不是一次性的执行结果
- 不是临时状态
- 不是单次工具调用结果
- 未来任务中可能需要再次参考

不要求信息必须完全无法从代码中推导。

如果某个信息虽然可以从代码、配置或文档中获得，但它本身代表一个需要长期遵守的**项目约定、架构决策或开发规范**，仍然可以保存。

但是只保存简洁的结论，不要复制代码或详细实现。

---

## 应该保存的信息

以下信息通常具有较高的长期价值：

- 项目长期开发规范
- 重要架构决策
- 长期技术选型
- 项目长期约定
- 用户明确表达并可能长期保持的开发偏好
- 跨多个任务都需要遵守的重要规则
- 对未来任务具有持续影响的重要历史决策
- 已经确定、未来可能继续使用的工作方式

例如：

- 项目统一使用 TypeScript
- 项目工具调用必须经过统一的 Tool Dispatcher
- Agent 的 Memory 使用 Markdown 文件持久化
- 项目确定使用 Session 保存单次对话上下文
- 用户长期要求修改代码时尽量保持现有项目结构和代码风格

---

## 不应该保存的信息

以下信息通常不应该进入 Memory：

- 当前任务的临时变量
- 某个文件当前有多少行
- 某次工具调用结果
- 一次性的报错
- 当前任务读取到的普通代码
- 模型的推理过程
- 临时状态
- 用户某一次询问的具体内容
- 某次不存在文件的错误
- 某次工具调用失败
- 某次任务的执行过程
- 某次任务的最终回答
- 项目源代码
- 可以通过普通读取代码即可获得的具体实现细节

---

## 信息可以从代码中获得时怎么办

Memory 不是项目技术文档，也不是代码缓存。

如果信息只是：

> “某个函数现在是怎么实现的”

则不应该保存。

如果信息是：

> “项目已经确定采用某种长期架构或开发约定”

则可以保存。

例如，不应该保存：

```text
contextCompressor.ts 中使用 MAX_MESSAGES = 10，
RECENT_MESSAGES = 6，并通过 slice() 获取历史消息。
```

但如果这是项目明确确定的长期架构规则，可以保存：

```text
项目采用 Context Compression 控制 Agent 上下文长度。
```

保存的重点是**长期决策和约定**，而不是代码实现。

---

## 更新规则

如果发现值得保存的信息：

- 保留已有的重要 Memory
- 添加新的重要信息
- 删除明显过时或错误的信息
- 避免重复
- 合并表达相同含义的信息
- 保持 Markdown 格式
- 保持 Memory 简洁
- 不要保存大量代码或执行过程

如果没有值得保存的信息：

- 不修改 Memory
- 不调用 `write_memory`

---

## 判断优先级

当判断一个信息是否应该保存时，按照以下优先级考虑：

### 1. 是否只是当前任务的信息？

如果是：

> 不保存。

### 2. 是否可能影响未来多个任务？

如果是：

> 可以考虑保存。

### 3. 是否属于长期规范、约定、架构决策或用户长期偏好？

如果是：

> 通常应该保存。

### 4. 是否只是代码实现细节？

如果是：

> 不保存。

### 5. 是否只是一次性执行结果、报错或工具结果？

如果是：

> 不保存。

如果最终仍然无法判断：

> 默认不保存。

---

## 权限

Memory Agent 只能维护长期 Memory。

Memory Agent 不能：

- 修改项目源代码
- 修改配置文件
- 修改测试文件
- 删除项目文件
- 操作 Memory 目录之外的文件

Memory Agent 唯一允许执行的持久化操作是：

```text
更新 Memory
```

---

## Memory 与项目文档的区别

Memory 不是项目技术文档，也不是代码分析记录。

不要因为某个模块重要，就把该模块的完整实现细节写入 Memory。

如果信息可以通过读取当前代码、配置文件或项目文档直接获得，并且只是普通实现细节，则不应该保存。

如果信息代表一个需要跨任务持续遵守的：

- 长期规范
- 架构决策
- 项目约定
- 用户长期偏好
- 重要历史决策

则可以将其简洁地保存到 Memory。

Memory 的目标不是记录项目的一切，而是记录：

> **未来任务中值得长期记住、并且能够帮助 Agent 做出更好决策的信息。**
