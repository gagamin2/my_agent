对 src/index.ts 和 src/agent/agent.ts 的说明（第 2 轮，覆盖第 1 轮）

一、src/index.ts（入口 / 启动器）
1. 职责单一：加载环境变量、引入依赖、启动 Agent、打印结果。
   - import "dotenv/config" 负责在程序启动时读取 .env，把 DEEPSEEK_API_KEY 等注入 process.env。
   - 引入 runAgent（Agent 主函数）与 readFile（文件读取工具，虽然本文件注释里也有直接调用它的示例）。
2. main() 是 async 函数，函数体里堆叠了多条被注释掉的历史测试指令，实际生效的只有一条：
   把当前这条“读取两个文件→写说明到 tests/text2.txt→再读→再写→循环往复”的指令交给 runAgent。
3. 最后 console.log(result) 输出 Agent 的最终返回。
4. 关键点：index.ts 不包含任何业务逻辑，它只负责“点火”，真正干活的是 agent.ts。

二、src/agent/agent.ts（Agent 核心 / 执行引擎）
1. 依赖与配置
   - 使用 OpenAI 兼容 SDK，baseURL 指向 https://api.deepseek.com。
   - apiKey 从 process.env.DEEPSEEK_API_KEY 读取。
   - 模型名硬编码为 deepseek-v4-pro。
2. 工具定义（tools 数组）
   - read_file：入参 filePath，读取指定文件内容。
   - write_file：入参 filePath + content，向指定文件写入完整内容。
   - 两个工具都通过 function-calling 方式暴露给模型。
3. executeTool(name, argumentsString)
   - 把模型给出的 JSON 参数解析为对象，再按工具名分发：
     read_file → readFile；write_file → writeFileTool；未知工具 → 抛错。
4. runAgent(userInput) 的主循环
   - 用 messages 数组保存 system + user 的完整对话历史。
   - MAX_TURNS = 10 是“保险丝”，最多跑 10 轮，防止无限循环。
   - 每一轮调用模型后依次做四类安全检查：
     a) 截断恢复：finish_reason === "length" 时调用 handleTruncation，多次截断则放弃（give_up）。
     b) Token 预算：checkBudget 累计输出 token，超限停止，接近阈值时打 tokenWarning。
     c) 无 tool_calls：直接 return message.content，任务正常结束。
     d) 循环检测：对每个 tool_call 用 createToolFingerprint 生成“工具名+参数”的指纹，再 checkLoop 判断是否重复调用；warn 时提醒，break 时直接停止。
   - 工具执行结果以 role:"tool" 消息追加回 messages，供下一轮模型参考。
   - 一轮结束后按需注入 LOOP_WARNING_PROMPT 或 TOKEN_WARNING_PROMPT 作为系统提醒。

三、两者关系与本次任务的关联
- index.ts 是“启动器”，agent.ts 是“引擎”；前者传入用户指令，后者负责多轮推理并调用 read_file/write_file 完成实际读写。
- 值得注意的是：本次用户指令本身就是一个“循环往复”任务。而 agent.ts 中的 MAX_TURNS、loopDetector（指纹 + checkLoop）正是为了拦截这种潜在死循环而设计的。也就是说，这个仓库的 Agent 既有“允许多轮调用工具”的能力，也有“检测重复调用并熔断”的保护机制。
- 对本次任务而言，合理做法是在完成若干轮“读→写”后主动停止并说明，而不是无限重复无意义的读写，否则会触发 Agent 自身的循环检测或保险丝。
